## Что построить

На ферме с готовым профилем можно отдельно проверить производство предметов без входа в стазис. Этот проверочный путь позволяет разработать и принять эмуляцию параллельно со снимками фермы; окончательная связка со стазисом выполняется в тикете 09.

## Критерии приёмки

- [x] Эмуляция производит предметы по среднему профилю в серверных тиках без адаптации к фактическому TPS.
- [x] Дробные накопители сохраняют доли предметов между обновлениями и выдают только целые предметы без округления скорости или случайных бросков.
- [x] Выход обновляется каждые 20 тиков по умолчанию; интервал эмуляции настраивается отдельно от интервала снимков профилирования.
- [x] Нормализация сохраняет тип предмета и отбрасывает зачарования, повреждения, названия и другие индивидуальные свойства.
- [x] Буфер ограничен свободной ёмкостью выходного контейнера и не создаёт бесконечное хранилище.
- [x] При заполнении выхода производство приостанавливается без потери или выбрасывания предметов и возобновляется после освобождения места.
- [x] Игроки и воронки могут извлекать предметы; внешнее добавление и изъятие в MVP не блокируются.
- [x] Проверочный запуск эмуляции без стазиса изолирован от окончательного пользовательского цикла и может быть удалён при интеграции без изменения поведения эмуляции.

## Реализация

- `emulation.ProfileEmulation` — чистое ядро, которое переиспользует стазис: `update(ticks, output)` сначала переносит буфер в выходной контейнер, затем, если буфер пуст, производит `ticks` тиков профиля. Накопители — `BigDecimal` от десятичного значения скорости: без дрейфа и без округления скорости.
- Буфер: целые предметы, не поместившиеся в выходной контейнер. Пока он не пуст, производство приостановлено (время не накапливается), поэтому буфер не превышает выработки одного обновления, не помещённой в выходной контейнер (решение: «ограничен свободной ёмкостью» трактуется как запрет копить выработку при заполненном выходном контейнере; требует подтверждения пользователя).
- `emulation.EmulationTrialService` + команды `/bake start-emulate <UUID>` / `/bake stop-emulate <UUID>` — только проверочный путь (согласовано с пользователем): только создатель, только `READY`, состояние фермы не меняется, чанк выхода загружен тикетом. Удаляется в #9 вместе с двумя ветками команд.
- `profiling.ChunkTickets` — подсчёт ссылок на тикеты чанков вынесен из `ProfilingService` и общий для профилирования и эмуляции.
- `emulation.PaperEmulationWorld` вставляет новые стаки `ItemStack.of(type)` порциями по максимальному стаку через `Inventory.addItem` и считает остаток.
- Настройка `emulation.update-interval` (20).

## Ручная приёмка в игре

1. Ферма в `READY`, механизм выключен, выходной контейнер пуст: `/bake start-emulate <UUID>`; через ~60 с в выходном контейнере ≈ 60 × скорость предметов (`/bake info`), простые стаки без компонентов.
2. Профиль с дробной скоростью < 1: предметы появляются только когда накопится целый.
3. Заполнить выходной контейнер до отказа: производство останавливается, ничего не выпадает; забрать предметы рукой или воронкой — поступление возобновляется.
4. `/bake stop-emulate <UUID>`: сообщение об остатке буфера, поступление прекращается.
5. Сломать выходной контейнер во время проверки: эмуляция останавливается с сообщением.
6. `emulation.update-interval: 100` в конфиге — предметы приходят порциями раз в 5 с.
