# Снимок и восстановление сущностей

Status: implemented (unit, Paper smoke and user manual acceptance passed)
GitHub: https://github.com/CheckSelfy/Bake-Mechanisms/issues/7
Branch: feature/5-7-farm-stasis

## Scope

Расширяет проверенный блочный снимок #5. Требуются выбор по пересечению габаритов, целые группы транспорт/пассажиры, отказ для неизвестных типов до изменения мира, удаление оригиналов и восстановление без дублирования. Формат привязан к Paper 26.3; перед обновлением сервера требуется явное восстановление всех ферм.

## Comments

- Начато после успешного серверного сценария #5. Эмуляция и буфер не изменяются.
- Добавлен `PaperEntitySnapshots`: выбор по пересечению `BoundingBox`, подъём до корня транспорта, проверка всей группы и сериализация корня с пассажирами только один раз. Игроки, неизвестные типы, поводки, невалидные/неперсистентные сущности и открытые инвентари транспорта отклоняются до изменения мира.
- Проверены на реальном Paper: корова, зомби, житель, железный голем, стойка для брони, обычная вагонетка, вагонетка с сундуком, вагонетка с воронкой, предмет в мире. Сохраняются UUID, расположение, имена/PDC, возраст, экипировка, свойства мобов и инвентари транспорта.
- Проверены корова с центром снаружи кубоида и транспорт с пассажиром вне кубоида. При стазисе удаляются все сохранённые UUID; при восстановлении проверяются связи, отсутствие лишних сущностей и отсутствие выпавших копий инвентаря.
- После искусственной ошибки, возникшей уже после размещения сущностей, они удаляются, возвращается заполнитель, снимок остаётся пригодным к повторной попытке. Повторная попытка успешно восстанавливает тот же состав.
- Используется публичный Paper API `UnsafeValues` (deprecated), изолированный и закреплённый за Paper 26.3. Миграции снимков между версиями нет; перед обновлением сервера требуется восстановить все фермы.
- Добавлены версионированный двоичный конверт и тесты топологии, запрета игроков/неподдерживаемых пассажиров, повреждения формата и удаления по UUID. Поддерживается чтение старого блочного снимка #5.
- `gradlew.bat build stasisSmoke`: успешно, маркеры `ENTITY_STASIS_SMOKE_PASSED` и `BLOCK_STASIS_SMOKE_PASSED`. Повторное чтение файлов проверено в новом реестре на работающем Paper; полный рестарт с буфером эмуляции относится к #9.
- GitHub Issue не изменён и не закрыт. Пользователь подтвердил успешную ручную приёмку в игре, включая предложенные проверки перезапуска в стазисе и сущностей на границе кубоида.
- При добавлении ульев проверены и разрешены также летающие пчёлы. В отдельном Paper-сценарии сохраняются UUID, имя и нектар летающей пчелы; хранимые в двух типах ульев пчёлы сохраняются в block NBT, не выпускаются при стазисе и корректно выходят после восстановления.
