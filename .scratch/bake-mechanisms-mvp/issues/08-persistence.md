## Что построить

Штатный перезапуск не стирает разметку, готовый профиль или уже накопленную эмуляцией выработку. Незавершённый замер не сшивается через рестарт, а корректно отменяется.

## Критерии приёмки

- [x] Данные каждой фермы хранятся в отдельном каталоге данных плагина: метаданные и профиль человекочитаемы, предметы и бинарные данные сохраняются в бинарной форме.
- [x] Отдельная база данных не требуется.
- [x] После штатного рестарта восстанавливаются разметка, создатель, профиль, буфер и дробные накопители (буфер и накопители — формат и восстановление; запуск эмуляции из них — #9).
- [ ] После рестарта эмуляция продолжается без сброса или повторного начисления уже сохранённой выработки — по решению пользователя проверочная эмуляция не возобновляется; `ProfileEmulation(profile, state)` + `emulation.dat` готовы для стазиса в #9.
- [x] Незавершённое профилирование после рестарта переходит в `NEEDS_PROFILING` и требует нового запуска.
- [x] Защита и тикеты загрузки отменённого профилирования после рестарта не остаются активными.
- [x] Поведение проверено реальным штатным перезапуском сервера; гарантии аварийного завершения в MVP не заявляются.

## Реализация

- `storage.FarmStorage`: `plugins/BakeMechanisms/farms/<UUID>/farm.yml` (YAML: id, создатель, состояние, мир, кубоид, выходной контейнер, профиль производства) и `emulation.dat` (бинарно: магия, версия, дробные накопители как точные десятичные строки, буфер выработки как int). Атомарная замена файлов через `.tmp`.
- Сохранение без профиля удаляет `emulation.dat`; при загрузке состояние эмуляции, не соответствующее профилю, — ошибка. Каталог без `farm.yml` (незавершённое первое сохранение) пропускается.
- Любая нечитаемая ферма проваливает загрузку целиком, плагин отключается и ничего не перезаписывает.
- `FarmRegistry`: слушатель изменений (плагин сохраняет каждую мутацию), `restore` с теми же правилами размещения, но без повторной проверки предела объёма; `PROFILING` → `NEEDS_PROFILING` при восстановлении.
- `ProfileEmulation.state()` / `ProfileEmulation(profile, EmulationState)`.
- Тикеты чанков и защита существуют только в памяти; `onDisable` отменяет профилирование и сохраняет `NEEDS_PROFILING`.

## Ручная приёмка в игре

1. Разметить ферму, довести до `READY`, `stop` сервера, запустить: `/bake info <UUID>` показывает тот же профиль и создателя; в `plugins/BakeMechanisms/farms/<UUID>/farm.yml` читаемые данные.
2. Запустить профилирование, остановить сервер посреди замера, запустить: ферма в `NEEDS_PROFILING`, механизм и выходной контейнер доступны игрокам, чанки не удерживаются плагином.
3. Испортить `farm.yml` — плагин отключается с сообщением, файл не перезаписан.
