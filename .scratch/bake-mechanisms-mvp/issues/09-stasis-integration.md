# Интеграция полного стазиса и персистентности

Status: implemented (unit tests; in-game acceptance pending)

Branch: feature/9-stasis-integration
Blocked by: #5, #6, #7, #8

## Что построить

Пользователь получает окончательный сквозной цикл: после профилирования оригинальная ферма исчезает в стазисе, эмуляция наполняет отдельный выход, а полный снимок и состояние производства переживают штатный рестарт и явное восстановление.

- [x] Переход `READY → STASIS` сохраняет полный снимок блоков и поддерживаемых сущностей до замены кубоида заполнителем.
- [x] Во время стазиса оригинальный механизм отсутствует, а эмуляция производит предметы в выход без одновременной работы оригинала.
- [x] Выходной чанк принудительно загружен на протяжении стазиса; тикеты чанков механизма сняты.
- [x] Штатный рестарт в `STASIS` восстанавливает снимок, буфер, дробные накопители и продолжает эмуляцию без потерь и дублирования.
- [x] Явное восстановление прекращает эмуляцию и возвращает механизм с блоками, внутренними контейнерами и сущностями.
- [x] Остаток буфера не сбрасывается при восстановлении и переносится в выход по мере наличия места.
- [x] При неудачном восстановлении заполнитель, снимок и буфер сохраняются до повторной попытки.
- [x] Временный проверочный запуск эмуляции без стазиса удалён или отключён; конечный пользовательский цикл не зависит от него.

## Comments

- Скопировано из GitHub Issue #9 (2026-11-10). GitHub Issue не изменён.
- Решения пользователя: остаток буфера после восстановления хранится отдельно от профиля (`drain.dat`), дробные доли отбрасываются; профилирование отклоняется, пока остаток переносится; состояние эмуляции пишется после каждого изменения; при недоступном выходе буфер сохраняется, перенос повторяется, создатель получает одно сообщение.
- Согласованные швы TDD: `StasisEmulationService`, `StasisService` (`StasisProduction`), `FarmStorage`, `ProfilingService`.
- Выходной чанк удерживается и пока переносится остаток буфера; тикет снимается, когда буфер пуст.
- Code review (standards + spec): остатки буфера повторно сохраняются при остановке сервера; при неудачном возврате заполнителя эмуляция не запускается и не возобновляется рядом с частью оригинала; исправлены устаревший абзац в `docs/development/stasis-integration.md` и сообщение (термин «буфер выработки»). Открытый вопрос: если выходной контейнер окончательно утерян после восстановления, перенос остатка повторяется бесконечно, выходной чанк остаётся загруженным, а профилирование недоступно — нужен выход (например, в #10). Оставлены без изменений замечания-вкусовщина (дублирование работы с тикетами, `Map<Material, Integer>` вместо типа буфера, адаптеры в плагине).
