# Защитить профилирование от подмены продукции через воронки

Status: implemented
GitHub: https://github.com/CheckSelfy/Bake-Mechanisms/issues/25
Branch: feature/25-profiling-input-protection

## Требования

- Каждый физический блок выхода расположен вне механизма и не дальше одного блока от него.
- Расстояние проверяется при разметке и перед профилированием; старые снимки не теряют возможность восстановления.
- Во время замера защищён кубоид механизма, расширенный на два блока по всем осям.
- Внешние воронки, возвратные цепочки и начальные запасы не увеличивают профиль.
- Штатные сбор продукции и разгрузка выходов работают; после завершения/отмены снимаются защита и тикеты.

## Решение

Выход — конечный получатель. Подавать в механизм и выходы разрешено только из инвентарей внутри
исходного механизма. Сборщики и подающие воронки должны входить в кубоид. Из выхода можно разгружать
предметы наружу, но возвращать их в механизм/выходы нельзя. Пограничные двойные сундуки и неоднозначные
начальные запасы отклоняются. Подбор новых предметов требует происхождения внутри механизма;
подброшенные игроками, старые и внешние предметы не считаются продукцией.

## Comments

- Скопировано из GitHub Issue #25. GitHub не изменён.
- По просьбе пользователя старый лут на земле больше не блокирует запуск: его UUID не получают
  доверие нового замера, поэтому сборщики его не подбирают и он не смешивается с новой продукцией.
- Реализовано от `main` (`c7da2b3`) в указанной отдельной ветке.
- Проверено: 190 unit-тестов, `build`, `entityNbtSmoke`, `stasisSmoke`; native-маркеры
  `PROFILING_INPUT_SMOKE_PASSED` и `PROFILING_NATURAL_INPUT_SMOKE_PASSED`.
- Отдельный headless-сервер на 25567: четыре извлечённые фермы кактуса/тростника прошли
  профилирование, стазис, учёт выработки и восстановление (`FARM_LAB_HEADLESS_PASSED`).
- Правила и ручная матрица: [docs/testing/profiling-input.md](../../../docs/testing/profiling-input.md).
- Неоднозначность начального снаряжения проверяется консервативно по типу предмета; совпадение
  прерывает замер с причиной. Действующая настройка событий воронок читается из закреплённого Paper.

- По последующей просьбе пользователя внутренние воронки разрешены с начальным запасом.
  Их содержимое передаётся как обычно и может влиять на профиль; внешняя подача остаётся запрещена.
