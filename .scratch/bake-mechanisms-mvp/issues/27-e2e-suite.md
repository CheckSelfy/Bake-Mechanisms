# Автоматизировать E2E-тесты полного цикла на Paper

Status: in progress (шаги 1–2 готовы и прогнаны на Paper; следующий — шаг 3)
GitHub: https://github.com/CheckSelfy/Bake-Mechanisms/issues/27
Связано с: #2, #11 (дополняет ручные correctness/performance-review #11/#12, не заменяет)

## Требования (из GitHub #27)

- Одна документированная команда: сборка JAR, подготовка изолированного Paper 26.3, запуск всего набора.
- Отдельные временные миры/каталоги; основной тестовый мир разработчика не меняется.
- Полный цикл: разметка → профилирование → `READY` → стазис → эмуляция → восстановление → `NEEDS_PROFILING`.
- Во время стазиса оригинала нет, продукция только от эмуляции.
- Производство против профиля за известное число тиков, включая дробные накопители.
- Переполнение выхода, приостановка и возобновление без потерь и дублирования.
- Восстановление блоков, внутренних контейнеров, поддерживаемых сущностей с NBT и связями транспорт/пассажиры.
- Рестарт во время стазиса сохраняет снимок, буфер и дроби; рестарт во время профилирования отменяет замер.
- Повторное профилирование после восстановления и безопасное удаление регистрации.
- Негативные сценарии: права создателя, отказ при неподдерживаемом содержимом до изменения мира.
- Ожидания по серверным тикам и наблюдаемым состояниям, не по настенному времени.
- При падении — понятная причина, логи и диагностика; временные процессы останавливаются.
- Зафиксирован успешный прогон на Paper 26.3; нестабильное и непокрытое перечислено явно.

## Исходное состояние (2026-11-11)

Большая часть сценариев уже автоматизирована, но разбросана по отдельным запускам:

| Существующее | Покрытие |
|---|---|
| `scripts/correctness-review.py` + `CorrectnessPlugin` (C01–C11) | разметка, права, профилирование, стазис, точная эмуляция с дробями, полный выход/возобновление, рестарт в `STASIS`/`PROFILING`, восстановление, повторный цикл, удаление |
| `correctness-review.py --short-profile-only` | отказ короткого полезного участка при включённом флаге |
| `gradlew stasisSmoke` | отказы снимков, неподдерживаемые блоки/сущности, пассажиры, таблички, поршни, поведение мобов |
| `gradlew entityNbtCapture` → `entityNbtSmoke` | NBT, UUID, деревья пассажиров через две JVM |

Пробелы относительно критериев:

- Нет одной команды: 4–5 запусков плюс ручной `test-worlds.py prepare --accept-eula`.
- `stasisSmoke`/`entityNbt*` переиспользуют фиксированные `run/stasis-smoke`, `run/entity-nbt-smoke`; порт 25566 зашит (конфликт с ручным farm-lab).
- Успех определяется финальным маркером — тихо пропущенная проверка незаметна.
- Отказ при неподдерживаемом содержимом проверяется через smoke-сервис, а не через команду игрока.
- Нет явной проверки «выход растёт ровно на величину эмуляции» и «нет дублирования» по сумме выход + буфер.
- Рестарт при свободном выходе (отсутствие offline-начисления) не проверяется.
- NBT/пассажиры проверены только в smoke, не в контексте полного цикла.
- Нет итоговой сводки причины падения и сбора логов; Gradle-задачи при падении ничего не собирают.
- `docs/testing/results.md` относится к #11 и предшествует #24/#26.

## План

1. **Оркестратор** `scripts/e2e.py`: один раз собирает JAR; новый каталог `run/e2e/<timestamp>/<suite>/`;
   свободный порт; наборы stasis-smoke → entity-nbt (capture + restore) → correctness (2 процесса) →
   short-profile; EULA только явным `--accept-eula`; остановка сервера/клиентов в `finally` и по Ctrl+C;
   `summary.md`/`summary.json` (статус, первая ошибка, хвост лога, артефакты, SHA-256); ненулевой код выхода.
2. **Единый протокол маркеров и матрица трассировки**: `E2E_PASS <id> tick=…` / `E2E_FAIL <id> reason=…`,
   файл ожидаемых ID ↔ критерии #27; оркестратор требует присутствия всех.
3. **Закрыть пробелы сценариев**: отказ `/bake` стазиса с command block/creeper через команду игрока и
   проверкой неизменности мира; явная проверка «только эмуляция»; рестарт при свободном выходе;
   «нет дублирования» по сумме; C13 (несколько выходов, #26), если ещё не покрыт драйвером.
4. **Стабильность**: 3 прогона подряд на чистых каталогах; естественные 12000 тиков наблюдения C02
   вынести за `--full`; нестабильное — в явный список.
5. **Документация и фиксация**: `docs/testing/e2e.md`, запись успешного прогона с SHA-256, список непокрытого
   (синтезированный клиентский ввод, C07 без естественной фермы брони, воронка/ручное извлечение).

## Открытые решения

- Python-оркестратор (выбрано для шага 1) vs Gradle-задачи; тонкая Gradle-обёртка — позже.
- Сокращённый прогон по умолчанию или всегда полный.
- Нужен ли CI (EULA, время прогона).
- Разделение работы с ответственным по GitHub (Молчанов Матвей).
