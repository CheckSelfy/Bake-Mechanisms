# Bake-Mechanisms

Серверный плагин для Paper 26.3, который снижает нагрузку от автоферм без входных ресурсов: профилирует производство предметов, заменяет исходный механизм заполнителем и эмулирует его выход.

## Сборка

Требуются macOS или Linux и установленная Java для запуска Gradle wrapper. Нужная JDK 25 загружается автоматически при первой сборке.

```bash
./gradlew build
```

Готовый плагин находится в `build/libs/bake-mechanisms.jar`. Paper API используется только при компиляции, поэтому дополнительных runtime-зависимостей у плагина нет.

## Локальный сервер Paper 26.3

Первоначальная настройка скачивает закреплённую стабильную сборку Paper 26.3 build 246 и нужный ей оригинальный сервер Mojang, проверяет их SHA-256 и принимает Minecraft EULA для локального сервера:

```bash
./scripts/setup-test-server.sh
./scripts/run-test-server.sh
```

Скрипт запуска собирает и развёртывает плагин через `./gradlew runServer`, после чего запускает сервер на JDK 25. Файлы сервера создаются в игнорируемом Git каталоге `server/`. Локальный сервер по умолчанию работает с `online-mode=false`. Для остановки сервера введите `stop` в его консоли.

Чтобы развернуть новую сборку, остановите сервер и снова выполните `./scripts/run-test-server.sh`. Если нужно только обновить JAR в `server/plugins/` без запуска сервера, используйте `./gradlew deploy`.

Paper 26.3 поставляется со встроенным spark, поэтому отдельно устанавливать плагин не нужно. После запуска используйте `spark tps` или `spark tickmonitor` в консоли сервера для наблюдения за MSPT.

## Разметка фермы

Команды доступны любому игроку; WorldEdit не нужен.

1. Получите выделитель: `/bake wand` (нужно свободное место в инвентаре).
2. Держа его в основной руке, выберите первый угол ЛКМ, второй — ПКМ. Границы включают выбранные блоки; порядок углов не важен.
3. Выберите внешний выходной контейнер через Shift+ПКМ выделителем. Альтернатива: посмотрите на контейнер в пределах 6 блоков и выполните `/bake output`.
4. Выполните `/bake register`. В ответе будут UUID фермы и состояние `NEEDS_PROFILING`.
5. Используйте `/bake list` и `/bake info <UUID>` для просмотра своих ферм. `/bake clear` сбрасывает незавершённое выделение. Алиас команды — `/bm`.

Выходом может быть обычный сундук, двойной сундук или бочка в том же мире, вне кубоида. Двойной сундук — один выход, обе половины должны находиться снаружи. Выход нельзя использовать повторно или включить в механизм другой фермы. Механизмы разных ферм не могут занимать общие чанки, даже на разной высоте.

Предел объёма задаётся параметром `max-mechanism-volume` в `plugins/BakeMechanisms/config.yml`, по умолчанию `262144` (`64×64×64`). Изменение применяется при перезапуске. Незавершённое выделение сбрасывается при выходе игрока или смене мира.

На этапе #3 регистрации хранятся в памяти до остановки сервера; сохранение после рестарта реализуется в #8. Профилирование, стазис и восстановление относятся к следующим задачам. Разметка сама по себе не доказывает отсутствие входных ресурсов и поддержку снимка фермы.

## Тесты

```bash
./gradlew test
```

На Windows используйте `gradlew.bat build` / `gradlew.bat test`. Для запуска wrapper нужна установленная Java; JDK 25 для компиляции и тестов Gradle загружает автоматически. Скрипты подготовки сервера написаны для Bash.

Тесты проверяют геометрию, конфликты, права создателя, обработчик выделителя и разрешение контейнеров через Paper API. Сценарий ручной проверки на сервере описан в [задаче #3](.scratch/bake-mechanisms-mvp/issues/03-farm-marking.md).
