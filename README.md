# Bake-Mechanisms

Серверный плагин для Paper 26.3, который снижает нагрузку от автоферм без входных ресурсов: профилирует производство предметов, заменяет исходный механизм заполнителем и эмулирует его выход.

## Сборка

Требуется установленная Java для запуска Gradle wrapper (macOS, Linux или Windows). Нужная JDK 25 загружается автоматически при первой сборке.

```bash
./gradlew build
```

Готовый плагин находится в `build/libs/bake-mechanisms.jar`. Paper API используется только при компиляции, поэтому дополнительных runtime-зависимостей у плагина нет.

## Локальный сервер Paper 26.3

Первоначальная настройка скачивает закреплённую стабильную сборку Paper 26.3 build 246 и нужный ей оригинальный сервер Mojang, проверяет их SHA-256 и принимает Minecraft EULA для локального сервера:

```bash
./scripts/setup-test-server.sh
./scripts/run-test-server.sh
```

На Windows (и на любой ОС без Bash) те же шаги выполняются задачами Gradle:

```powershell
.\gradlew.bat setupServer   # только подготовка сервера
.\gradlew.bat runServer     # подготовка (если нужна), сборка, развёртывание и запуск
```

`setupServer` скачивает отсутствующие файлы, проверяет SHA-256 уже скачанных и не перезаписывает существующие `eula.txt` и `server.properties`. `runServer` вызывает её автоматически. Сервер читает команды из консоли, поэтому запускайте его в интерактивном терминале и останавливайте командой `stop`.

Скрипт запуска собирает и развёртывает плагин через `./gradlew runServer`, после чего запускает сервер на JDK 25. Файлы сервера создаются в игнорируемом Git каталоге `server/`. Локальный сервер по умолчанию работает с `online-mode=false`. Для остановки сервера введите `stop` в его консоли.

Чтобы развернуть новую сборку, остановите сервер и снова выполните `./scripts/run-test-server.sh`. Если нужно только обновить JAR в `server/plugins/` без запуска сервера, используйте `./gradlew deploy`.

Paper 26.3 поставляется со встроенным spark, поэтому отдельно устанавливать плагин не нужно. После запуска используйте `spark tps` или `spark tickmonitor` в консоли сервера для наблюдения за MSPT.

## Разметка фермы

Команды доступны любому игроку; WorldEdit не нужен.

1. Получите выделитель: `/bake wand` (нужно свободное место в инвентаре).
2. Держа его в основной руке, выберите первый угол ЛКМ, второй — ПКМ. Границы включают выбранные блоки; порядок углов не важен.
3. Выберите внешний выходной контейнер через Shift+ПКМ выделителем. Альтернатива: посмотрите на контейнер в пределах 6 блоков и выполните `/bake output`.
4. Выполните `/bake register`. В ответе будут UUID фермы и состояние `NEEDS_PROFILING`.
5. Используйте `/bake list` и `/bake info <UUID>` для просмотра своих ферм. `/bake clear` сбрасывает незавершённое выделение. Алиас команды — `/bm`.

Выходом может быть обычный сундук, двойной сундук или бочка в том же мире, вне кубоида. Двойной сундук — один выход, обе половины должны находиться снаружи. Выход нельзя использовать повторно или включить в механизм другой фермы. Механизмы разных ферм не могут занимать общие чанки, даже на разной высоте.

Предел объёма задаётся параметром `max-mechanism-volume` в `plugins/BakeMechanisms/config.yml`, по умолчанию `262144` (`64×64×64`). Изменение применяется при перезапуске. Незавершённое выделение сбрасывается при выходе игрока или смене мира.

Регистрации пока хранятся в памяти до остановки сервера; сохранение после рестарта реализуется в #8. Стазис и восстановление относятся к следующим задачам. Разметка сама по себе не доказывает отсутствие входных ресурсов и поддержку снимка фермы.

## Профилирование

`/bake profile <UUID>` запускает профилирование фермы из `NEEDS_PROFILING`, `/bake cancel <UUID>` отменяет его. Обе команды доступны только создателю.

- Профилирование длится ровно 3600 серверных тиков. Чанки механизма и выходного контейнера принудительно загружены тикетами плагина (с учётом общих чанков у одновременно профилируемых ферм).
- Запуск отклоняется, если внутри кубоида стоит игрок или выходной контейнер больше не совпадает с разметкой.
- Во время профилирования игроки (включая создателя и creative) не могут войти или телепортироваться в кубоид, ломать и ставить блоки, нажимать механизмы, пользоваться вёдрами и сущностями внутри, открывать или ломать выходной контейнер и ставить блоки вплотную к нему. Взрывы не разрушают выходной контейнер; взрывы внутри механизма не блокируются.
- Начальное содержимое выходного контейнера — базовый снимок, оно не считается продукцией. Выходной контейнер читается каждые `profiling.snapshot-interval` тиков (20 по умолчанию) и в конце профилирования.
- Полезный участок длится до последнего снимка перед первым полностью заполненным (каждый слот содержит полный стак). Обычные паузы до заполнения остаются в статистике.
- Профиль хранит среднюю скорость в предметах на 20 тиков по типу предмета, без зачарований и других компонентов. Опыт не учитывается. Смотрите его через `/bake info <UUID>`.
- Профиль без произведённых предметов отклоняется. Если `profiling.reject-short-useful-segment: true`, отклоняется и полезный участок короче `profiling.min-useful-ticks` (600). По умолчанию эта проверка выключена.
- Успех → `READY`, отказ, отмена, потеря выходного контейнера или остановка сервера → `NEEDS_PROFILING`. Защита и тикеты снимаются, механизм не изменяется. Создатель получает сообщение, если он в сети.
- Известные ограничения защиты: въезд в кубоид на транспорте, вход в игру или возрождение внутри кубоида, косвенные воздействия (жидкости, поршни, TNT, подожжённый снаружи). Фермы, зависящие от случайных тиков или спавна мобов, могут работать медленнее вдали от игроков: держите создателя рядом с фермой во время профилирования.

## Тесты

```bash
./gradlew test
```

На Windows используйте `gradlew.bat build` / `gradlew.bat test`. Для запуска wrapper нужна установленная Java; JDK 25 для компиляции и тестов Gradle загружает автоматически. Скрипты подготовки сервера написаны для Bash; на Windows используйте `gradlew.bat setupServer` и `gradlew.bat runServer`.

Тесты проверяют геометрию, конфликты, права создателя, обработчик выделителя и разрешение контейнеров через Paper API, расчёт профиля, жизненный цикл профилирования с тикетами, защиту области и чтение выхода. Сценарий ручной проверки на сервере описан в [задаче #3](.scratch/bake-mechanisms-mvp/issues/03-farm-marking.md).
