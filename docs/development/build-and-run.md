# Сборка, локальный сервер и релизы

Пользовательская установка описана в [README](../../README.md#установка). Здесь — работа с исходниками
и тестовым сервером. Термины проекта находятся в [глоссарии](../../GLOSSARY.md), решение о снимках
и заполнителях — в [ADR-0001](../adr/0001-replace-farms-with-snapshots-and-fillers.md).

## Сборка и тесты

Нужна установленная Java для запуска Gradle wrapper. Toolchain JDK 25 загружается автоматически
при первой сборке; для работы самого Paper-сервера нужна Java 25. Поддерживаются Windows, Linux
и macOS. Зависимости первой сборки требуют сети.

```bash
./gradlew build
./gradlew test
```

На Windows используйте `gradlew.bat build` и `gradlew.bat test`. Основной результат —
`build/libs/bake-mechanisms.jar`. Paper API не упаковывается в JAR: его предоставляет сервер,
дополнительные плагины-зависимости не нужны.

Unit-тесты проверяют геометрию и конфликты разметки, права создателя, выделитель и меню,
расчёт профиля, игровые тики, жизненный цикл и загрузку чанков, защиту, дробные накопители,
буфер выработки, ошибки сохранения/восстановления и удаление регистрации.

Проверки на настоящем Paper запускаются отдельно:

```bash
./gradlew stasisSmoke
./gradlew entityNbtSmoke
```

`stasisSmoke` создаёт отдельный сервер в `run/stasis-smoke/`, проверяет снимки, сущности, заполнитель,
защиту, профилирование и эмуляцию, затем штатно останавливает сервер. `entityNbtSmoke` выполняет
проверку сущностей в двух процессах с настоящим перезапуском. Эти тесты не меняют мир из `server/`.
Тестовые плагины не включаются в основной JAR.

## Локальный Paper-сервер

Скрипты для Bash:

```bash
./scripts/setup-test-server.sh
./scripts/run-test-server.sh
```

Эквивалентные задачи Gradle, в том числе для Windows без Bash:

```powershell
.\gradlew.bat setupServer
.\gradlew.bat runServer
```

Подготовка скачивает закреплённые Paper 26.3 build 246 и сервер Mojang, проверяет SHA-256 и создаёт
файлы локального сервера в игнорируемом каталоге `server/`. Подготовка создаёт `eula.txt` с принятием
[Minecraft EULA](https://aka.ms/MinecraftEULA), если файла ещё нет; ознакомьтесь с ней перед запуском.
Существующие `eula.txt` и `server.properties` не перезаписываются. Локальный сервер по умолчанию
использует `online-mode=false`.

`runServer` выполняет подготовку, сборку, развёртывание и запуск на JDK 25. Используйте интерактивный
терминал: сервер читает команды из консоли, штатная остановка — `stop`. Для обновления сборки
остановите сервер и снова выполните `runServer` либо `scripts/run-test-server.sh`.
Задача `./gradlew deploy` обновляет основной JAR в `server/plugins/` без запуска сервера.

### Тестовый мир

`runServer` разворачивает вместе с основным плагином построитель `bake-farm-lab.jar`. При первом
запуске он создаёт отдельный мир `farm_lab` с четырьмя фермами кактуса/тростника, включая контрольные
копии, и двумя мобофермами скелетов/зомби. Источники:
[PPL9](../../test-worlds/ppl9/README.md) и [мобофермы PPL9](../../test-worlds/ppl9-mobs/README.md).
Игрок, вошедший в другой мир, переносится в `farm_lab`. Последующие запуски сохраняют изменения мира.

Подсказки доступны через `/farmlab list`; полный цикл, сравнение с контролями, рестарт и запись
результатов описаны в [руководстве лаборатории](../testing/manual-farm-lab.md).
Для отдельной ручной копии также можно использовать `python scripts/farm-lab.py run`
и подключиться Minecraft 26.3 к `127.0.0.1:25566`.

Для полной перестройки **после остановки сервера**:

```bash
./gradlew resetFarmLab
```

Задача удаляет мир `farm_lab`, данные построителя, регистрации ферм Bake Mechanisms в этом мире
и сохранённые позиции выхода игроков. После перестройки старая разметка недействительна.
При запущенном сервере задача отказывается удалять данные. Построитель и остальные тестовые
плагины предназначены только для локальных тестов, а не для установки на игровой сервер.

Paper 26.3 включает spark. Для наблюдения за сервером используйте `spark tps` или
`spark tickmonitor` в консоли. Протокол замеров и сохранённые результаты находятся в
[документации производительности](../testing/performance.md).

## GitHub Actions

[CI](../../.github/workflows/ci.yml) запускает `./gradlew build` на Java 25 для каждого pull request
и push в `main`. Неуспешные тесты делают проверку неуспешной. JAR успешного запуска находится
на странице запуска: **Artifacts → bake-mechanisms**. GitHub скачивает артефакт ZIP-архивом;
перед установкой извлеките `bake-mechanisms.jar`.

## Выпуск релиза

Локальная версия задаётся в `gradle.properties`. Для релиза поставьте тег на проверенный коммит:

```bash
git tag v0.2.0
git push origin v0.2.0
```

Это пример формата тега, а не указание текущей опубликованной версии.
[Release workflow](../../.github/workflows/release.yml) принимает `v<major>.<minor>.<patch>`
и необязательный суффикс, например `v0.2.0-rc1`. Он передаёт версию без `v` через `-Pversion=…`,
выполняет сборку/тесты, проверяет версию в `plugin.yml` внутри JAR и затем создаёт GitHub Release
с `bake-mechanisms.jar` и автоматическим описанием. Версия с суффиксом публикуется как pre-release.
При неподходящем теге или ошибке сборки релиз не создаётся.

Если ошибочный тег ещё не стал опубликованным релизом, исправьте причину и при необходимости
переставьте тег: `git push --delete origin v0.2.0`, удалите локальный тег и создайте его на нужном
коммите. Уже опубликованные версии лучше сохранять неизменными и выпускать исправление новым тегом.
Развёртывание на игровом сервере остаётся ручным: остановите его, замените JAR в `plugins/`
и запустите снова.
