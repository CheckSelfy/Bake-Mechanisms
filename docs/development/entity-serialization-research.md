## Actual API behavior

`serializeEntity(root, PASSENGERS)` checks valid/persistent state for the whole passenger stream, calls native `saveAsPassenger(output, true, false, false)`, and encodes the resulting compound with `MCUtil.serializeTagToBytes`. It is the native persistence representation, not a dump of every runtime field. `PASSENGERS` includes descendants, not the vehicle above the supplied entity. `FORCE` bypasses normal valid/persistent restrictions; `MISC` and `PLAYER` admit otherwise unsaveable types. None adds omitted runtime properties. Players cannot be restored. The current plugin correctly climbs to the root, validates all members and supplies only `PASSENGERS`. [Sources: CraftMagicNumbers and UnsafeValues above; supplementary flag documentation](https://jd.papermc.io/paper/26.3/io/papermc/paper/entity/EntitySerializationFlag.html).

`deserializeEntity(bytes, world, true, true)` retains UUID fields and passenger compounds, creates entities with a native LOAD request, then recursively creates and mounts passengers. It does not insert them into the world. With `preserveUUID=false`, the helper removes UUID for every recursively created member. With `preservePassengers=false`, the root passenger tag is removed. It rejects newer data versions and runs the entity data converter for older data. These flags preserve identities and tree data; they do not prove successful insertion, absence of an existing UUID, preservation of every mounting position, or completeness of state. [Source: pinned CraftMagicNumbers above.]

With `includeAll=true`, native Entity saving includes UUID, position and world UUID. Rotation, motion and custom name follow native persistence too. A mounted passenger's saved X/Z are taken from its vehicle, so arbitrary pre-save passenger offsets are not guaranteed. Paper also explicitly saves ticks lived, visible-by-default, persistent invisibility, maximum air, visual-fire override, origin, spawn reason, spawner/portal origin and freeze lock. PDC is stored as `BukkitValues` through `CraftEntity.storeBukkitValues` and read back. Therefore these properties should be tested, not presumed unsupported. [Sources: Entity persistence patch and CraftEntity above.]

## Concrete loss risks and boundaries

| State | Evidence and consequence | Required policy/test |
| --- | --- | --- |
| Minecart maximum speed, slow-when-empty, flying and derailed velocity modifiers | Actual build's `vehicle.minecart.AbstractMinecart` constructor initializes these fields; `addAdditionalSaveData`/`readAdditionalSaveData` only handle display block/offset, flipped rotation, HasTicked and Paper friction. The patch adds the fields without persistence. | Compare public getters before/after deserialize. Reject non-default unsupported values before mutation, or extend the payload and restore explicitly. Applies to all three supported cart types. |
| Minecart damage | Actual build's `VehicleEntity` has damage accessors but no additional persistence writer, and AbstractMinecart's writer does not write damage. | Set nonzero damage in a probe and verify rejection or explicit restoration. Default-only fixtures cannot expose this loss. |
| Active mob target | Actual build's `Mob.addAdditionalSaveData` saves loot pickup, persistence, drop chances, leash, home, handedness, loot table, NoAI, awareness and peaceful override, but not `target`. | A target inside the tree and one outside it both need explicit policy. UUID preservation does not restore a Java object reference. |
| Brain memories and activities | Actual build's `Brain.pack()` visits memories through `Brain$1`, which adds a memory only when `MemoryModuleType.canSerialize()` is true. `MemoryMap`'s codec requires a memory codec. The activity/sensor/behavior runtime is not a complete persisted machine checkpoint. | Test persistent villager home/job/meeting memories and their dimensions, while documenting AI recomputation. Do not promise every runtime memory/activity survives. |
| Fixed pose; last damage event | CraftEntity's fixed pose setter writes `entity.fixedPose`; Entity's persistence writer does not save that field. Last damage event is a field on the CraftEntity wrapper. | Test/reject fixed pose where exposed; exclude historical event objects from a persistent-state guarantee. |
| External relationships | PASSENGERS traverses only riding descendants. Leash data can name another entity/block; mob homes, bee hive/flower positions and villager memories can point outside the mechanism. Persisting a reference does not snapshot its target or reserve it for the restoration time. | Keep leash rejection; add explicit supported policies for world/block/entity references. Test a changed/missing external target. |
| Scoreboard team | Entity load resolves a team in the world's scoreboard and Paper config can disallow nonplayer members. The snapshot does not own the scoreboard. | State a boundary or validate prerequisites; test with the actual server scoreboard setting. |

The bytecode observations above are reproducible with the repository's JDK 25 `javap.exe -p -c -classpath server/versions/26.3/paper-26.3.jar <class>`. Classes: `net.minecraft.world.entity.vehicle.minecart.AbstractMinecart`, `net.minecraft.world.entity.vehicle.VehicleEntity`, `net.minecraft.world.entity.Mob`, `net.minecraft.world.entity.ai.Brain`, `net.minecraft.world.entity.ai.Brain$1`, `net.minecraft.world.entity.ai.memory.MemoryMap`. The pinned Paper patches and CraftEntity sources above provide the corresponding upstream context. A patch's absence alone was not treated as proof that vanilla does not save a field.

Round-tripping serialized bytes or comparing snapshots helps find losses during native load, but cannot detect state omitted by the initial writer. `CraftEntitySnapshot.create` passes `includeAll=false`, so its SNBT excludes UUID/world/position; `getAsString()` simply returns `CompoundTag.toString()`, with no canonical-order API contract. A complete oracle needs separate public property assertions, UUID/tree/location checks and a semantic representation of persisted item/PDC data. A successful string comparison is not proof of full state preservation. [Source: CraftEntitySnapshot and Entity persistence patch above.]

## Required verification matrix

### Losses observed in real-server probes

The implementation session's early `EntityNbtCheck` runs on the pinned server observed the following mismatches. The run directory is reused and earlier logs were overwritten, so these observations are reported as session evidence rather than linked to a retained passing/failing report. They require explicit regression assertions in the final retained run:

- `Item.canMobPickup=false` became `true`. [CraftItem](https://github.com/PaperMC/Paper/blob/b31b4b5/paper-server/src/main/java/org/bukkit/craftbukkit/entity/CraftItem.java) reads/writes native `canMobPickup`; the [ItemEntity patch](https://github.com/PaperMC/Paper/blob/b31b4b5/paper-server/patches/sources/net/minecraft/world/entity/item/ItemEntity.java.patch) initializes it to true. Inspection of actual build 246's `ItemEntity` persistence methods confirms they omit this field. A false value must be rejected or separately stored.
- `Bee.timeSinceSting=113` became `0`. [CraftBee](https://github.com/PaperMC/Paper/blob/b31b4b5/paper-server/src/main/java/org/bukkit/craftbukkit/entity/CraftBee.java) reads/writes native `timeSinceSting`. Actual build 246's `Bee.addAdditionalSaveData` writes nectar/stung booleans, pollination/hive/crop counters and persistent anger but omits the sting timer; preserving `HasStung` alone therefore does not preserve time until death. The [Bee patch](https://github.com/PaperMC/Paper/blob/b31b4b5/paper-server/patches/sources/net/minecraft/world/entity/animal/bee/Bee.java.patch) also adds a rolling override that the writer does not store. Reject a nonzero timer or nondefault override unless explicitly restored.
- A sparse villager inventory item in slot 7 moved to slot 1. Actual build 246's `InventoryCarrier.writeInventoryToTag` uses `SimpleContainer.storeAsItemList`, which writes nonempty stacks without slot indices. The reader clears the container and calls `addItem` for each list entry. This both compacts gaps and can merge compatible stacks; adjacent partial identical stacks also need a regression test even when there are no empty gaps. The pinned [SimpleContainer patch](https://github.com/PaperMC/Paper/blob/b31b4b5/paper-server/patches/sources/net/minecraft/world/SimpleContainer.java.patch) is upstream context; this conclusion comes from inspecting the actual artifact's vanilla `SimpleContainer` and `npc.InventoryCarrier` bytecode, not from the patch alone. Compare full per-slot inventory against a detached native roundtrip before accepting a snapshot.

Use the `javap` reproduction command above with `net.minecraft.world.entity.item.ItemEntity`, `net.minecraft.world.entity.animal.bee.Bee`, `net.minecraft.world.SimpleContainer`, and `net.minecraft.world.entity.npc.InventoryCarrier` to inspect the exact writers/readers. These are concrete persistence boundaries, not hypothetical losses.

Every type needs UUID; exact world and position; yaw/pitch; velocity; custom component name and visibility; PDC containing typed nested/array values; scoreboard tags; persistence; gravity; invulnerability; silence; fire/freeze state; and relevant default and non-default flags. Assert by UUID immediately after restore before ticking, then after a controlled tick. These are test requirements, not source-based guarantees.

## Expansion to spawnable living types (build 246)

The expansion policy should be based on the pinned API's `EntityType.isAlive()` and `isSpawnable()`, followed by explicit exclusions and state checks. These methods merely return the enum's `living` and `independent` fields; neither tests persistence fidelity. `PLAYER` remains forbidden. A type being unusual, a boss, or available only through commands is not evidence that its native persistent state cannot be restored. This section is source/bytecode research, not a passing integration matrix.

The following evidence was obtained with the JDK 25 command above against the exact server artifact. API signatures and enum flags were inspected with the same command using classpath `server/libraries/io/papermc/paper/paper-api/26.3.build.246-stable/paper-api-26.3.build.246-stable.jar`. ### State checks needed beyond adding enum values

- **Tameable consistency:** `TamableAnimal.addAdditionalSaveData` stores `Owner` and `orderedToSit` as `Sitting`. Its reader derives tame status solely from whether an owner reference exists and sets sitting pose from the ordered flag. `CraftTameableAnimal.setTamed(true)` allows no owner; `setOwnerUUID` does not itself set tame status. Consequently native load can change legal API-created states. Compare `isTamed`, owner UUID and `isSitting` with a detached native load before accepting capture. An offline owner reference is persistent identity, not proof that the external owner is snapshotted. [Pinned wrapper](https://github.com/PaperMC/Paper/blob/b31b4b5/paper-server/src/main/java/org/bukkit/craftbukkit/entity/CraftTameableAnimal.java).
- **Horses:** `animal.equine.AbstractHorse` explicitly writes `EatingHaystack`, `Bred`, `Temper`, `Tame`, `Owner`, and `Bukkit.MaxDomestication`; the reader restores those fields. A blanket claim that maximum domestication is omitted is false for this build. Test chest-bearing variants and all per-slot equipment/items separately. Rearing/mouth/jump/eating animation counters are runtime fields beyond this writer. [Pinned wrapper](https://github.com/PaperMC/Paper/blob/b31b4b5/paper-server/src/main/java/org/bukkit/craftbukkit/entity/CraftAbstractHorse.java).
- **All inventories:** extend exact detached per-slot comparison to every supported `InventoryHolder`, including allays/piglins where exposed, horses and nautiluses. The existing villager compaction finding is about `InventoryCarrier`/`SimpleContainer` list encoding; it should not be generalized into a claim that every inventory writer compacts slots. Ensure no open viewers, and avoid removal-time duplicate drops for newly supported inventory/equipment-bearing entities. [Pinned inventory API](https://github.com/PaperMC/Paper/blob/b31b4b5/paper-api/src/main/java/org/bukkit/inventory/InventoryHolder.java).
- **Sheep:** `animal.sheep.Sheep` writes/reads `Sheared` and `Color`. Its `eatAnimationTick` is omitted, and the pinned Bukkit Sheep API has no public eating-timer getter. Color/wool loss is not justified by this evidence; animation/goal progress belongs to the runtime boundary. [Pinned API](https://github.com/PaperMC/Paper/blob/b31b4b5/paper-api/src/main/java/org/bukkit/entity/Sheep.java).
- **Chicken:** `animal.chicken.Chicken` explicitly writes/reads `IsChickenJockey`, `EggLayTime`, variant and sound variant. The public getters permit independent assertions for all four. Do not reject a nondefault egg countdown as unsupported without contrary real-server evidence. [Pinned API](https://github.com/PaperMC/Paper/blob/b31b4b5/paper-api/src/main/java/org/bukkit/entity/Chicken.java).

No source inspection here establishes an exhaustive guarantee for every AI goal, transient combat timer or brain activity in every living class. A broad supported-type policy can still preserve native persistent data while rejecting proven public-state losses before world mutation; its guarantee should name that boundary, and the real-server matrix must enumerate every pinned living/spawnable type, including command-only types such as `GIANT`, rather than silently skipping unfamiliar enum values.
