# Автоматическая часть correctness-review #11

Актуальное расширение и результаты: [acceptance follow-up](acceptance-2026-11-11.md). Основной прогон теперь включает **два рестарта / три JVM**, реальную выгрузку воронкой, восстановление с полным выходом и отказ файловой системы через production-команды. Отдельный `--client-acceptance-only` использует настоящие сетевые клики/Shift/команды/перемещение и проверяет полученные сообщения/action bar; визуальный рендеринг клиента не проверяется.

Запуск использует настоящий Paper 26.3 build 246, основной JAR, отдельный `BakeCorrectness` и `BakeTestFixtures`. Проверочные классы не попадают в основной JAR. Нужны JDK 25 и Python 3.11+; сторонних Python/Node-пакетов нет.

Сначала подготовьте кэш через [обычную процедуру](README.md), включая принятие EULA. Затем:

```text
python scripts/correctness-review.py --server run/correctness-review --cache-server run/fixture-lab
python scripts/correctness-review.py --server run/correctness-short-profile --short-profile-only
python scripts/correctness-review.py --server run/correctness-client --client-acceptance-only --port 25568
python scripts/correctness-review.py --server run/correctness-mobs --mob-farms-only --port 25570
```

Каталог `--server` должен отсутствовать: скрипт отказывается менять существующий запуск. Он собирает JAR, проверяет SHA-256 закреплённых Paper/Mojang, копирует принятое EULA и серверные библиотеки, создаёт новые миры и слушает только `127.0.0.1:25566`. Порт должен быть свободен. Сервер работает в offline mode, без whitelist; два минимальных клиента — `ReviewCreator` и `ReviewOther`, оба не OP. `allow-flight=true` нужен неподвижным клиентам без физического движка. Подготовка использует консоль, тестируемые команды — реальные Bukkit `Player.performCommand` с проверкой создателя основным плагином.

Драйвер выполняет прогрев 12000 тиков и отдельное наблюдение естественного выхода 12000 тиков. Каждый полный замер занимает 3600 серверных тиков. Для сокращения настенного времени используется `tick rate 100`; это не performance-review. `randomTickSpeed` остаётся 3. Два игрока находятся рядом с разными фермами, инструмент снимает собственные тикеты перед проверками.

Во время прогрева также профилируются две отдельные контрольные регистрации без производителей: пустой выход обязан дать отказ; насыщенный контрольными камнями выход — профиль до последнего неполного снимка (200 тиков, `0.1 / 20 тиков`), без плоского хвоста. Контрольные регистрации удаляются до естественного наблюдения. Второй запуск `--short-profile-only` проверяет, что тот же короткий полезный участок отклоняется при включённом флаге минимума 600 тиков; он заканчивается после 3600 тиков без основного цикла/рестарта. Запуски используют один порт и выполняются последовательно.

Далее проверяются регистрация, права, отмена, параллельное профилирование, исключение базовых предметов, стазис обеих ферм, точная выработка и дроби, заполнение выхода и возобновление, восстановление, штатное завершение процесса и новый запуск, отмена незаконченного замера при старте, повторный цикл и удаление с подтверждением. Для независимости повторного цикла от случайной кладки в его замер явно добавляются контрольные предметы; это не измерение естественной производительности. В конце проверяется неизменность опыта обоих игроков и отсутствие предметов, выброшенных при полном выходе.

Сохранённый `emulation.dat` сравнивается побайтно до/после рестарта при полном выходе и остановившемся производстве. Дополнительный второй рестарт проверяет свободный выход: до первого обновления инвентарь и дроби не меняются за измеренный offline-интервал, затем выработка сверяется с фактическими тиками. Интервал сохраняется в `offline-interval.json`.

## Границы

- Выделитель настоящий, но его клики и попытки ломания подаются синтезированными Bukkit events. Это проверка зарегистрированных обработчиков с настоящим игроком, не проверка клиентского ввода, расстояния взаимодействия или отрисовки.
- В обычном режиме клиенты поддерживают подключение, подтверждения загрузки/телепортации/чанков и keepalive. Режим `--client-acceptance-only` добавляет реальные протокольные команды, ЛКМ/ПКМ, Shift, перемещение, извлечение из контейнера и запись полученных сообщений/action bar в `client-control/*.messages`. ID пакетов и формат полей сверены с закреплённым Mojang JAR и его `packets.json`. Клиенты привязаны к protocol 777; визуальный рендеринг Minecraft не проверяется.
- Контрольный повреждённый именованный зачарованный меч добавляется в **выход куриной фермы** во время отдельной проверки нормализации. Драйвер различает исходный предмет и новый предмет без metadata. Это дополнительная серверная проверка преобразования, **не прохождение C07 с естественным производством брони**. Естественные яйца/кактусы измеряются раньше, без вмешательства.
- Ключевые состояния проверяются через публичный формат `FarmStorage`, инвентари и тикеты через Paper API. Ни registry, ни сервисы основного плагина не заменяются моками; reflection/NMS в драйвере нет.
- Для отказов снимков используйте также `gradlew.bat stasisSmoke` / `./gradlew stasisSmoke`: реальный native capture с отказом записи, частичный отказ восстановления с повтором, неизвестные block entities/сущности, инвентари, пассажиры, таблички, расширенные блоки и движущиеся поршни. Fault injection заменяет только границу сохранения/размещения отдельного smoke-сервиса, не production-команды.
- Полная матрица C01–C12 шире этого драйвера. Неотработанные варианты перечисляются в [результатах](results.md), а не объявляются пройденными.

## Артефакты

`fixture-console.log` содержит три запуска основного прогона; `restart_ready.log`, `open_restart_ready.log` и `correctness_passed.log` — их раздельные логи. `clients.log` содержит подключения клиентов. В логах `REVIEW_PASS` включает ID проверки и серверный тик; `ACCOUNTING` — фактические целые предметы и дроби. Любой `REVIEW_CORRECTNESS_FAILED`, `FIXTURES_ERROR`, преждевременный выход сервера или отсутствие итогового маркера завершает скрипт с ошибкой. Миры, конфиги и данные тестовых плагинов остаются в каталоге запуска. Для повтора выберите новый каталог; не смешивайте данные разных запусков.
