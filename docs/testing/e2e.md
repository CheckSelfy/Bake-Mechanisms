# E2E-набор полного цикла (#27)

Одна команда собирает все JAR и последовательно запускает существующие проверки на настоящем Paper 26.3 build 246. Каждый набор получает **новый** каталог; основной `server/` и ручной farm-lab не затрагиваются. План развития и непокрытые критерии — [тикет #27](../../.scratch/bake-mechanisms-mvp/issues/27-e2e-suite.md).

Нужны JDK 25 и Python 3.11+, сторонние пакеты не нужны. Сеть нужна только для первой загрузки Gradle/Paper.

```text
python scripts/e2e.py --accept-eula --java-home <путь к JDK 25>
```

На Windows с несколькими Python: `py -3.13 scripts/e2e.py ...`. `--java-home` можно опустить, если `JAVA_HOME` уже указывает на JDK 25; другая версия отклоняется до сборки.

`--accept-eula` означает принятие [Minecraft EULA](https://aka.ms/MinecraftEULA) для одноразовых локальных серверов. Принятие сохраняется в кэше (`run/e2e-cache/`, `--cache`); там же лежат Paper и Mojang JAR, проверенные по закреплённым SHA-256, и библиотеки, распакованные Paper. Без флага и без ранее принятого EULA в кэше скрипт отказывает.

## Наборы

| Набор | Процессы | Что проверяет |
|---|---|---|
| `stasis-smoke` | 1 | Снимки блоков и сущностей, отказ записи, таблички, расширенные блоки, поршни, поведение мобов (как `gradlew stasisSmoke`) |
| `entity-nbt` | 2: `capture` → `restore` | NBT, UUID и пассажиры через штатный перезапуск JVM ([entity-nbt.md](entity-nbt.md)) |
| `correctness` | 3: `restart-ready` → `offline-ready` → `correctness-passed` | C01–C11 с двумя headless-клиентами ([correctness-review.md](correctness-review.md)); два настоящих рестарта: при полном выходе (C10) и при свободном выходе без offline-начисления (C10_OFFLINE); отказ `/bake stasis` при неподдерживаемом содержимом (C05_UNSUPPORTED) |
| `short-profile` | 1 | Отказ короткого полезного участка при включённом флаге |

`--suite <имя>` (повторяемый) запускает только выбранные наборы. `--skip-build` переиспользует `build/libs`. `--fail-fast` пропускает оставшиеся наборы после первого провала. Последующие процессы одного набора после провала не запускаются, потому что зависят от предыдущих.

## Результат и диагностика

Каталог запуска — `run/e2e/<время>/` (`--output`, должен отсутствовать):

- `summary.md` / `summary.json`: итог, статус и длительность каждого процесса, число найденных ожидаемых маркеров, коммит (с пометкой о грязном рабочем дереве), версии Java/Paper, SHA-256 JAR;
- для провала — причина (первая строка-маркер ошибки и следующие строки стека, либо список отсутствующих маркеров, код выхода или срабатывание сторожа) и последние 30 строк консоли;
- `<набор>/<процесс>.log` (копия `logs/latest.log`), `<процесс>.console.log`, `clients.log`, а также миры и данные плагинов для разбора.

- раздел «Критерии #27»: какие маркеры этого прогона подтверждают каждый критерий тикета и какой пробел остаётся. Матрица — `COVERAGE` в `scripts/e2e.py`.

Код выхода 0 только при PASS всех выбранных наборов. Процесс считается пройденным, если в логе есть **все** ожидаемые маркеры (точное совпадение токена, например `REVIEW_PASS C08_PAUSE`), нет маркеров ошибки и ошибок загрузки плагина, а сервер завершился с кодом 0. Одного финального маркера недостаточно. `scripts/test_e2e.py` сверяет списки маркеров с исходниками тестовых плагинов: новая проверка, которую не добавили в оркестратор, роняет тест, а не пропадает молча.

## Ожидания и остановка

Проверки внутри плагинов отсчитывают серверные тики. Таймауты оркестратора служат только сторожем от зависания: 600 с настенного времени без строки прогресса, 3600 с на процесс. Оркестратор запускает сервер и клиентов в отдельной группе процессов. При Ctrl+C, провале или срабатывании сторожа он отправляет `stop`, через 120 с завершает процесс принудительно, а затем пишет сводку. Сетевым наборам выбирается свободный порт на `127.0.0.1`; smoke-наборы работают с `server-port=0`.

## Границы

Набор переиспользует существующие проверки и наследует их границы: синтезированные Bukkit events вместо клиентского ввода, C07 без естественной фермы брони и другие, см. [результаты #11](results.md#оставшаяся-приёмка). Не покрытые пока критерии #27 перечислены в тикете.
