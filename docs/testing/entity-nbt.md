# Матрица сохранения сущностей (#22)

Версия проверки: Paper **26.3 build 246**, Java 25. Сериализация использует публичный Paper API,
сохраняет UUID и полные предметы; нормализация продукции эмуляции к снимку не применяется.

## Как запустить

```powershell
.\gradlew.bat build entityNbtSmoke stasisSmoke --console=plain
```

`entityNbtSmoke` запускает **два отдельных процесса** в `run/entity-nbt-smoke/`:

1. Создаёт все 96 поддерживаемых типов: 91 живой тип и пять неживых. Две овцы проверяются
   отдельно — взрослая нестриженая и молодая стриженая, разных цветов. До стазиса сохраняет независимый
   эталон `plugins/BakeStasisSmoke/entity-audit/baseline.yml`, затем сохраняет снимок, удаляет
   оригиналы, проверяет заполнитель/отсутствие дропов и штатно останавливает сервер.
2. Загружает снимок с диска в новый сервис. До явного восстановления проверяет отсутствие сущностей.
   Восстанавливает, сравнивает с эталоном и выполняет второй полный цикл. Проверяет отказы для
   неподдерживаемых свойств без изменения мира и публикации активного снимка.

Тестовый мир изолирован от `server/`. Тестовый плагин не входит в основной JAR. Повторный запуск
пересоздаёт только свою тестовую площадку и деактивирует незавершённые снимки предыдущей проверки.
`entityNbtCapture` отдельно выполняет первую фазу. Для диагностики уже сохранённого снимка вторую
можно запустить через `entityNbtSmoke -x entityNbtCapture`; JAR в тестовом сервере при этом должен
соответствовать проверяемой сборке.

Успех: `ENTITY_NBT_CAPTURE_PASSED`, затем `ENTITY_NBT_RESTART_PASSED`.
Логи: `run/entity-nbt-smoke/logs/entity-capture.log` и `logs/latest.log`.

## Общие проверки

Для каждого типа проверяются UUID, тип, мир, координаты, yaw/pitch, скорость, Adventure-имя и его
видимость, строка и массив байтов в PDC, scoreboard tags, persistence, gravity, invulnerability,
glowing, silent. Координаты/углы сравниваются с точностью 0.0001, чтобы учесть float-представление поз.

Для живых сущностей: здоровье, возраст там, где применим, атрибут масштаба, активный эффект
(тип, длительность, усилитель, ambient/particles/icon), AI и despawn; для Mob также awareness.
Состав и число экземпляров сравниваются с эталоном: каждая сущность должна существовать ровно один раз.

## Матрица типов и дополнительных свойств

| Тип | Дополнительно проверяется на реальном сервере |
| --- | --- |
| `COW` | Отрицательный возраст, age lock, love ticks, здоровье/эффект/scale |
| `ZOMBIE` | Baby, подбор предметов, ломание дверей, горение днём; все шесть обычных слотов экипировки и drop chances |
| `VILLAGER` | Возраст, профессия, биомный тип, уровень, опыт, restocks; все слоты плотно заполненной части инвентаря; рецепт с результатом и ингредиентами, uses/max uses, XP/reward, multiplier, demand, special price, ignore discounts; репутация по UUID; HOME/JOB_SITE с миром и координатами |
| `IRON_GOLEM` | Player-created, здоровье/эффект/scale |
| `ARMOR_STAND` | Small, arms, base plate, visible; все шесть поз, блокировка снятия шлема, все шесть обычных слотов экипировки |
| `MINECART` | Display block/data/offset, скорость движения; проверка отказов для нестандартных speed/slow/flying/derailed и ненулевого damage |
| `CHEST_MINECART` | Все слоты инвентаря, включая последний; полные компоненты предметов; удаление без дублирующего дропа |
| `HOPPER_MINECART` | То же плюс enabled=false |
| `ITEM` | Полный ItemStack, pickup delay, owner/thrower UUID, unlimited lifetime, player pickup, здоровье предмета |
| `ARROW` | Damage, critical, pierce level, pickup status, shooter UUID, base potion; общий UUID/позиция/скорость/PDC и свойства проверены после настоящего рестарта. Добавлено для естественных скелетных ферм; остальные неаудированные снаряды остаются запрещены. |
| `BEE` | Возраст, nectar, stung, anger, cannot-enter-hive ticks, crops grown, ticks since pollination, hive/flower координаты |

В предметах намеренно заданы имя/цвет, lore, зачарование, повреждение и PDC. Сравнивается полное
семантическое равенство `ItemStack`, а не только материал/число предметов и не порядок байтов NBT.
Строковые представления registry-объектов содержат адреса JVM, поэтому тип эффекта/профессии/варианта
сравнивается по registry key.

Связи проверяются на вложенном дереве `MINECART → ZOMBIE → ARMOR_STAND`, совместно с независимыми
группами. Проверяются UUID каждого участника, порядок пассажиров, прямые/обратные связи и отсутствие
дубликатов после восстановления и повторного цикла. Старый `stasisSmoke` дополнительно покрывает
пересечение кубоида телом при центре снаружи и откат после ошибки уже после появления сущностей.

## Расширение на живые существа

Проверены **все 91 создаваемый живой тип** из закреплённого API, кроме `ENDER_DRAGON`.
Это явный список в `PaperEntitySnapshots.supportedTypes()`: обновление API не разрешит новый тип
автоматически. Unit-тест обнаружит появление ещё не проверенного живого типа.

Для всех типов общий эталон проверяет свойства, перечисленные выше, после штатного перезапуска
и повторного стазиса. Дополнительные нестандартные состояния:

| Группа | Дополнительная проверка |
| --- | --- |
| Овцы | Цвет, стрижка, взрослый/детский возраст; две овцы с разными состояниями |
| Куры | Холодный вариант, таймер следующего яйца |
| Приручаемые | Приручение, UUID хозяина; сидячая поза кошки/волка/попугая |
| Лошади и родственные | Domestication, jump strength, седло, броня лошади; сундук и его содержимое у вьючных |
| Кошки и волки | Вариант и цвет ошейника |
| Кролики, грибные коровы, лисы | Вид/вариант |
| Козы | Сохранение снятого рога и screaming |
| Панды | Основной и скрытый гены |
| Тропические рыбы | Рисунок и оба цвета |
| Криперы | Powered, максимальное время запала, радиус взрыва |
| Эндермены | Переносимый блок |
| Снежные големы | Состояние тыквы |
| Медные големы | Степень окисления |

Остальные типы, включая рыб, враждебных мобов, наутилусов, манекен и иссушителя, проходят общий
цикл с UUID, именем, PDC, координатами, здоровьем/эффектом/атрибутом масштаба и применимыми возрастом,
AI, инвентарём и хозяином. Перечень реально проверенных типов выводится в лог как `LIVING_AUDIT_TYPES`.

## Состояния, отклоняемые до изменения мира

| Состояние | Причина/действие |
| --- | --- |
| Тип вне списка, в том числе неподдерживаемый пассажир или игрок | Нет проверенного сериализатора. Убрать сущность/пассажира |
| Invalid/nonpersistent, поводок, открытый инвентарь транспорта | Нельзя безопасно снять полный снимок. Завершить взаимодействие |
| Закреплённая поза `hasFixedPose()` | Не входит в native NBT. Снять фиксацию |
| Индивидуальные collision exemptions | Не входят в NBT. Снять исключения |
| `Item.canMobPickup() == false` | Paper восстанавливает `true`. Убрать предмет |
| Пчела: ненулевой `timeSinceSting` или принудительный `rollingOverride` | Эти значения не переживают native load. Убрать пчелу/снять override |
| Житель: native roundtrip меняет инвентарь | NBT уплотняет список и объединяет совместимые стеки. Уплотнить инвентарь и объединить стеки; сравниваются все слоты |
| Вагонетка с несгенерированной добычей | Сначала открыть, чтобы содержимое было определено до снимка |
| Вагонетка: нестандартные maxSpeed, slowWhenEmpty, flying/derailed modifiers или damage | Проверяется через отделённую native-десериализацию с сохранением UUID; значения должны совпасть до публикации снимка |
| Пассажир: native roundtrip меняет текущие координаты | Такое возможно сразу после посадки. Дождаться завершения посадки или высадить пассажира |
| Дракон Края | Составное тело и внешний контроллер боя не входят в обычную группу снимка |
| Скрипун с сердцем или в активном состоянии | Внешняя связь с сердцем и активность не восстанавливаются одним NBT |
| Медный голем в состоянии работы с контейнером | Дождаться `IDLE`; состояние взаимодействия теряется |
| Приручение/хозяин/сидячая поза или инвентарь любого живого существа меняются при native roundtrip | Неполное/несогласованное состояние отклоняется, оригинал сохраняется |
| Неподдерживаемый возраст | Например, отрицательный возраст лягушки, попугая, странствующего торговца, верблюда-кадавра или зомби-наутилуса сбрасывается NBT; их обычное взрослое состояние поддержано |

Native-проверка вагонеток/пассажиров создаёт только отделённые объекты: они не появляются в мире,
не удаляют оригиналы и не занимают UUID в реестре сервера.

Перед восстановлением проверяется, не занят ли сохранённый UUID уже существующей сущностью.
При конфликте восстановление отклоняется **до остановки производства и любых изменений мира**:
чужая сущность не удаляется откатом. Серверный сценарий намеренно создаёт конфликт, проверяет отказ,
удаляет только свой проверочный объект и успешно повторяет восстановление.

## Активные цели и работа ферм

Активная цель больше не запрещает стазис. `SnapshotPayload` версии **3** сохраняет для каждой группы
связи `UUID моба → UUID цели` рядом с native NBT. Форматы 1/2 и старые снимки без конверта читаются;
в старых снимках отсутствующие ссылки не угадываются, AI заново ищет цель.

Восстановление идёт в два этапа: сначала появляются **все** группы и пассажиры, затем подключаются
цели. Поэтому цель может быть в другом дереве транспорта и быть восстановлена позже своего преследователя.
До замены мира возможность установить текущую цель проверяется на отделённой копии моба.

Используется обычный `Mob.setTarget` с проверкой getter. Для мобов с Brain (например, пиглинов, хоглинов,
вардена, лягушки, аксолотля и бриза) в этой сборке Paper публичный setter не обновляет `ATTACK_TARGET`.
Узкий адаптер `PaperMobTargets` обращается к **публичным** native-методам/полям через reflection,
проверяет регистрацию памяти и UUID результата; приватные поля и `setAccessible` не используются.
Это ограниченное исключение из подхода «только Paper API», привязанное к Paper 26.3 build 246.
Несовместимость обнаруживается до удаления оригиналов; формат NBT остаётся непрозрачным для плагина.

Цель вне механизма сохраняется только как ссылка: стазис её не удаляет и не добавляет в снимок.
При восстановлении живая доступная цель в том же мире подключается снова. Если она исчезла, умерла,
выгрузилась, сменила мир, стала неуязвимой, либо игрок вышел/перешёл в creative или spectator,
ссылка сбрасывается с записью в лог; ферма восстанавливается, дальше цель выбирает AI.
Внешние сущности не создаются и не телепортируются. Пропажа цели **внутри** снимка считается ошибкой
восстановления, а не допустимой потерей данных.

Серверный NBT-сценарий сохраняет **90 активных целей** всех представленных Mob, включая Brain-мобов,
после настоящего перезапуска. Проверены цель вне кубоида, её сохранность во время стазиса и рестарта,
а затем успешное восстановление после удаления внешней цели.

Одна ссылка атаки не описывает всё поведение. Крипер избегает кошки через `AvoidEntityGoal`, а жители
реагируют на видимого зомби через восприятие Brain. `stasisSmoke` дополнительно проверяет реальные тики:

- **Крипер/кошка:** сохраняется штатный avoid goal, другие цели убраны только в тесте для исключения
  случайного блуждания. Контроль без кошки — крипер стоит; с кошкой — увеличивает расстояние до неё как минимум до 6 блоков.
  Одинаковые проверки проходят до стазиса и после восстановления обоих UUID.
- **Слайм/голем:** слайм сам выбирает голема и приближается. После восстановления та же цель должна
  быть видна сразу по getter, затем слайм снова приближается. Цель вручную не назначается.
- **Жители/зомби:** три взрослых жителя в ячейках видят неподвижного зомби. Задана недавняя память сна,
  а cooldown обнаружения голема очищен одинаково в обоих этапах. Проверяется реальное появление
  железного голема до стазиса и после восстановления. Зомби защищён от солнечного горения.

Площадки используют chunk tickets и нулевые activation ranges **только на отдельном smoke-сервере**,
чтобы мобам не требовалось присутствие игрока. Игровые настройки сервера пользователя не меняются.
Итоговый маркер: `MOB_BEHAVIOR_SMOKE_PASSED`; при тайм-ауте или гибели участника задача падает.
Источники и детали: [исследование целей](../development/mob-target-research.md).

## Граница гарантии

Гарантия относится к сохраняемому Minecraft/Paper NBT и перечисленным проверенным свойствам на
закреплённой версии. Это не остановка каждой Java-переменной AI: пути, сенсоры, анимации, текущие
активности и несериализуемые Brain memories пересоздаются как при обычной загрузке чанка.
Исторические Bukkit event objects и произвольные metadata сторонних плагинов не входят в NBT;
для пользовательских сохраняемых данных нужен PDC.

HOME/JOB_SITE, hive/flower и owner/thrower сохраняются как ссылки/координаты. Снимок не сохраняет
внешний объект по такой ссылке и не откатывает мир вне механизма. Scoreboard tags проверены;
определения команд scoreboard и их внешнее состояние снимку не принадлежат. Межверсионный перенос
снимков не гарантируется: перед обновлением сервера оригиналы нужно восстановить.

Матрица фиксирует реально проверенные значения; она не является доказательством сохранения всех
возможных комбинаций свойств, новых полей будущего Paper или произвольного состояния других плагинов.
При добавлении типа/свойства нужны новый сценарий и обновление матрицы.

Основания и точные первичные источники: [исследование pinned Paper](../development/entity-serialization-research.md).
Пересечение с #10 ограничивается повторным жизненным циклом; удаление регистрации здесь не меняется.
