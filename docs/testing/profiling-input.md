# Защита профилирования от внешних предметов (#25)

Нужен Paper 26.3 build 246, Java 25 и свежий `build/libs/bake-mechanisms.jar`.
Проверяется действующая настройка мира `hopper.disable-move-event: false`, включая наследование
настроек Paper. Плагин читает её через публичные члены закреплённой версии Paper; несовместимая
версия или отключённые события воронок приводят к отказу запуска замера.

## Подготовка

1. Разметьте полный механизм, включая растения/мобов, воду, внутренние инвентари, сборщики,
   подающие воронки и весь путь движения вагонеток/мобов.
2. Выберите выход снаружи, вплотную к границе: каждый его блок должен попадать в кубоид,
   расширенный на один блок по каждой оси. У двойного сундука проверяются обе половины.
3. Зарегистрируйте `/bake register Test25`. Уберите предметы из внутренних инвентарей.
   Ножницы в раздатчике допустимы; яйца/шерсть/тростник в сборщиках перед стартом — нет.
   Начальное содержимое выхода можно оставить: оно станет базой, а не продукцией.
   Лежащий лут можно оставить: до конца замера сборщики не подбирают старые предметы и они
   не смешиваются со свежей продукцией. После окончания/отмены обычный подбор восстанавливается.
4. Отойдите от кубоида больше чем на два блока, учитывая ширину игрока. Выполните
   `/bake profile Test25`. В защитной области не должно быть других игроков, механизмов или
   выходов других зарегистрированных ферм. Активные защитные области не должны пересекаться.

Старые регистрации с далёкими выходами сохраняют возможность загрузки/восстановления снимка,
но новый замер потребует удаления регистрации и корректной разметки.

## Ручные проверки

Каждый отказ старта должен оставить `NEEDS_PROFILING`. После устранения причины запуск должен работать.

| Сценарий | Ожидаемый результат |
|---|---|
| Выход дальше одного блока; дальняя половина двойного сундука | Регистрация отклонена |
| Предметы в начальной внутренней воронке/бочке/вагонетке | Старт отклонён с причиной, предметы сохранены |
| Старый лут на земле внутри, в том числе того же типа, что продукция | Старт разрешён; старый лут не подбирается сборщиками и не увеличивает профиль |
| Воронка снаружи направлена в выход/механизм, даже пустая | Старт отклонён; включите подающий сборщик в механизм |
| Готовая внешняя цепочка выходит наружу и возвращается в выход | Старт отклонён из-за внешнего подающего звена |
| Предметы, брошенные вторым игроком из-за границы, попали к сборщику | Не подбираются сборщиком и не смешиваются с новой продукцией |
| Старые внешние предметы принесены водой | Не увеличивают профиль |
| Игрок пытается менять блоки/открывать соседнюю бочку в двухблочном поясе | Действие запрещено на время замера |
| Штатный внутренний сборщик подаёт свежую продукцию в выход | Продукция доходит до выхода и появляется в профиле |
| Заранее установленная разгрузка из выхода наружу | Разрешена; возвращать содержимое в выход нельзя |
| Шерсть от овцы, стриженной раздатчиком с ножницами | Сбор работает, ножницы изнашиваются |
| Яйцо от курицы, рост/сбор кактуса и тростника | Обычная продукция собирается |
| Сущность фермы выходит за исходный кубоид | Замер прекращён с причиной; расширьте разметку |
| В продукцию попадает тип предмета начального снаряжения или ножницы | Замер прекращён: запас неотличим от продукции |
| `/bake cancel Test25` или конец замера | Область и контейнеры снова доступны; транспорт работает как обычно |

Не подбрасывайте предметы административными `/item`, `/give`, командами summon с NBT или тестовым
плагином: прямые записи стороннего кода не относятся к изолируемому ванильному транспорту.
Профиль по-прежнему измеряет прирост содержимого выходов; разгрузка продукции во время замера
может занижать скорость. Для проверки точной скорости оставьте выход с достаточным свободным местом.

Начальное снаряжение мобов допускается, пока не попадает в продуктовый поток. Проверка по типу
предмета намеренно консервативна: если настоящая продукция совпадает с типом начального снаряжения,
замер тоже прервётся. Уберите такой запас перед запуском. Карманы жителей допускаются: они не
передаются в воронки и не выпадают при смерти. Остальные начальные инвентари сущностей должны быть пусты.

## Автоматические проверки

```text
./gradlew build entityNbtSmoke stasisSmoke
python scripts/farm-lab.py headless --server run/profiling-input-lab --cache-server server --port 25567
```

Для headless-прогона используйте новый каталог и свободный порт. Он запускает отдельный сервер,
не меняя ручной мир. Тестовый драйвер после прогрева очищает начальный запас и лежащие предметы
перед профилированием; основной плагин ничего автоматически не удаляет.

- Unit-тесты проверяют расстояние/границы/двойной сундук, направления транспорта, происхождение,
  смешивание, подброс игроком и очистку при отмене.
- `PROFILING_INPUT_SMOKE_PASSED` на настоящем Paper: проверка живой настройки воронок, отказы
  начального запаса, настоящие внешние воронки и возвратная цепь, старые внешние предметы двух
  типов, смешивание, базовое содержимое выхода и его разрешённая разгрузка. За 3600 тиков
  профиль содержит только новую продукцию; защита и дополнительные тикеты освобождаются.
- `PROFILING_NATURAL_INPUT_SMOKE_PASSED`: настоящая стрижка овцы раздатчиком, сбор шерсти и яйца,
  отмена обоих замеров с освобождением тикетов.
- `FARM_LAB_HEADLESS_PASSED`: четыре извлечённые фермы кактуса/тростника, профилирование,
  стазис, учёт выработки и восстановление. Это функциональный тест с ускоренным ростом после
  обычного прогрева, а не эталон ванильной производительности.

Снятие защиты не перезапускает уже остановившуюся физику воды/поршней; при необходимости заново
обновите соответствующий механизм. Предметы не удаляются и не получают постоянных служебных меток.
