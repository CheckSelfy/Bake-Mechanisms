# Слайм-заполнитель стазиса (#32)

Нужны Paper 26.3 build 246, Java 25 и свежий `build/libs/bake-mechanisms.jar`.
Обычная команда `/bake stasis <ферма>` теперь заменяет весь кубоид зелёным слаймом.
`/bake unstasis <ферма>` возвращает оригинальные блоки, инвентари и сущности.

## Быстрая визуальная проверка

В отдельной локальной копии сервера:

```text
python scripts/farm-lab.py run --server run/slime-manual --cache-server server --port 25567
```

Подключитесь Minecraft 26.3 к `127.0.0.1:25567`. Выполните `/slimegallery 1`, затем
`/slimegallery 2` … `/slimegallery 9`. OP не нужен; включается creative/полёт, камера смотрит на лицо.
Вернуться к фермам можно через `/farmlab setup`. Сервер останавливается `/farmlab stop`.

| № | Ширина × высота × глубина | Проверить |
|---|---|---|
| 1 | 3×3×3 | Упрощённые глаза и рот, зелёные промежутки |
| 2 | 5×5×5 | Небольшое центрированное лицо |
| 3 | 10×10×10 | Стандартные пропорции и прозрачная оболочка |
| 4 | 20×20×20 | Крупные квадратные глаза, ровные границы материалов |
| 5 | 15×5×10 | Широкая низкая форма, лицо остаётся по центру |
| 6 | 5×20×5 | Высокая форма, глаза остаются квадратными |
| 7 | 30×5×3 | Узор на длинной поверхности, отсутствие выхода за границы |
| 8 | 2×2×2 | Двухцветное тело без обязательного лица |
| 9 | 4×7×6 | Чётные/нечётные стороны, автоматическое лицо на восточной грани |

Осмотрите переднюю, заднюю, боковые и верхнюю грани, прозрачность и сердцевину. На передней
грани находятся две отдельные тёмные квадратные области глаз и рот; между ними зелёные блоки.
Лицо рисуется на одной грани. На маленьких регионах упрощается, при ширине/высоте меньше 3 отсутствует.

Галерея — отдельный вспомогательный плагин `bake-slime-gallery.jar`, автоматически устанавливаемый
только скриптом тестового мира. Он создаёт самостоятельный мир `bake_slime_gallery`, сохраняет его
и не перестраивает при повторном посещении/перезапуске. Это визуальные образцы без регистрации ферм.
Проверяйте защиту и восстановление на настоящей ферме либо через автоматические тесты ниже.
Не устанавливайте тестовые плагины на игровой сервер. В основном JAR галереи нет.

## Настройка и сохранение

Раздел `stasis.filler` в `plugins/BakeMechanisms/config.yml`:

```yaml
stasis:
  filler:
    front: AUTO
    pattern: BANDS
    patch-size: 3
    palette:
      shell: LIME_STAINED_GLASS
      shade: GREEN_STAINED_GLASS
      face-glass: BLACK_STAINED_GLASS
      core: LIME_TERRACOTTA
      accent: GREEN_CONCRETE
      face: BLACK_CONCRETE
```

`AUTO` выбирает сторону с наибольшим числом выходных контейнеров. Двойной сундук даёт один голос,
бочка тоже считается выходным контейнером. Сторона определяется по центру контейнера относительно
кубоида; на углу выбирается направление с большим выступом за границу, при равенстве — по правилу
ниже. Контейнеры строго сверху/снизу, без смещения за горизонтальные границы, не голосуют.
При равенстве голосов предпочтение получает более широкая грань (`SOUTH` при размере X ≥ Z,
иначе `EAST`), если она входит в число победителей; затем действует порядок `NORTH`, `SOUTH`,
`EAST`, `WEST`. Если горизонтальных голосов нет, используется более широкая грань.
В визуальной галерее выходных контейнеров нет, поэтому там тоже действует выбор широкой грани.
Можно выбрать `NORTH`, `SOUTH`, `EAST` или `WEST`. `BANDS` создаёт плавные ступенчатые полосы,
`PANELS` — более крупные повторяющиеся участки. `patch-size` — от 1 до 64 блоков. Узор зависит только
от локальных координат и настроек, а не от позиции или UUID мира. Углы/рёбра используют общий цвет.

Стеклянные `shell`, `shade`, `face-glass` образуют наружную поверхность. Плотные `core`, `accent`,
`face` используются только внутри; `face` — подложка за наружным тёмным стеклом. Разрешены стекло,
бетон без суффикса `_POWDER` и терракота. Сыпучие блоки, контейнеры, редстоун, slime/honey blocks,
воздух и другие материалы с механиками отклоняются при запуске плагина. Непрозрачная оболочка тоже
отклоняется. Обычное окрашенное стекло не добавляет отскок/липкость, тики или поверхность для спавна
мобов сверху. Все клетки заполнены полными блоками; ни воздуха, ни сущностей/анимаций нет.

Измените настройки и перезапустите сервер: они применяются к **следующим входам в стазис**.
В `stasis.yml` формата 3 сохраняются версия рисунка, фактическое направление, палитра и размер/тип
узора. Существующий заполнитель не перекрашивается. При ошибке восстановления используется его
сохранённое оформление, даже если текущая конфигурация другая. Форматы 1/2 читаются как старый
bedrock-заполнитель; такие снимки можно восстановить, после нового профилирования/стазиса появится слайм.
Бинарный формат снимка исходной фермы не менялся.

## Функциональная проверка в Minecraft

1. Профилируйте настоящую ферму и сохраните содержимое выходного контейнера для сравнения.
2. Выполните `/bake stasis <ферма>` снаружи: весь исходный кубоид занят заполнителем, выход не изменён.
3. Попробуйте сломать/поставить блоки в survival и creative, взорвать заполнитель, сдвинуть его
   поршнем, залить водой/лавой. Блоки заполнителя и выхода защищены; сам выход доступен для предметов.
4. Убедитесь, что эмуляция продолжает производить предметы без работающего оригинального механизма.
5. Перезапустите сервер: узор, направление лица и защита прежние.
6. Выполните `/bake unstasis <ферма>` снаружи: исходные блоки, инвентари и сущности вернулись,
   профиль сброшен. Смените палитру, заново профилируйте и войдите в стазис: применяется новый вид.

## Автоматические проверки и визуальные артефакты

```text
./gradlew build correctnessJar slimeGalleryJar stasisSmoke entityNbtSmoke
python scripts/check-slime-gallery.py --server run/slime-gallery-check --cache-server server --port 25567
python scripts/farm-lab.py headless --server run/slime-farm-check --cache-server server --port 25567
```

Используйте новые каталоги для проверок, запускайте серверы на одном порту по очереди.
Unit-тесты проверяют все размеры, симметрию/центрирование, три отдельных компонента лица,
локальность координат, безопасную палитру, сохранение/чтение оформления и откат после смены настроек.
Проверки защиты зависят от кубоида и не привязаны к материалу заполнителя.

`SLIME_FILLER_SMOKE_PASSED` проверяет настоящие блоки девяти регионов, попытку поршня и взрыв,
сохранение выхода, снятие оригинальных инвентарей без копий, чтение сохранённой палитры,
частичную ошибку восстановления и повторное полное восстановление. Дополнительный NBT-тест
в двух процессах проверяет рестарт с активным заполнителем и возврат сущностей.

`SLIME_GALLERY_RESTART_PASSED` подтверждает загрузку отдельного плагина, команду обычного игрока,
создание галереи и повторное посещение после чистого перезапуска. Это протокольная проверка,
не проверка отрисовки Minecraft-клиента. `FARM_LAB_HEADLESS_PASSED` проверяет полный цикл четырёх ферм.

Native-тест экспортирует **реальные блоки** в
`run/stasis-smoke/plugins/BakeStasisSmoke/slime-gallery.json`. На Windows схему лиц можно построить:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/render-slime-preview.ps1
```

Результат — `run/issue32-slime-faces.png`. Это схема геометрии для проверки пропорций; текстуры,
прозрачность и окончательный внешний вид принимаются в Minecraft через галерею.
